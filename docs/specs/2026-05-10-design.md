# Pure-OCaml SQL Engine — v1 Design

**Date:** 2026-05-10
**Status:** Draft for implementation
**Companion:** `ROADMAP.md` tracks every decision and deferred item as a checklist.

---

## 1. Goals and non-goals

### Goals

A pure-OCaml SQL engine, embeddable as a library, that runs on Linux for
development and on MirageOS unikernels for deployment. v1 supports tables,
indexes, CRUD, joins, and ACID transactions. Single-process, single-writer,
multi-reader. The storage layer is independently useful as an OCaml ordered
KV store with MVCC.

### Non-goals (v1)

- SQLite file-format compatibility (we use our own format).
- Source-to-source translation of SQLite C (concept port only).
- Multi-process or networked access.
- Server / wire protocol.
- Full SQL standard conformance.
- Full-text search (deferred to v2).
- WAL / write-ahead log (deferred; design hooks preserved).

`ROADMAP.md` enumerates every other deferred item.

## 2. Architecture

Four horizontal layers. Lower layers know nothing about upper layers.

```
┌─────────────────────────────────────────────────────────────┐
│  SQL surface                                                │
│    Parser  →  Sema  →  Planner  →  Exec                    │
│  Inputs: SQL text, params                                   │
│  Output: result rows / row count                            │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Relational layer                                           │
│    Catalog · Row codec · Index-key codec · Cursor wrappers  │
│  Inputs: typed plan ops, txn handle                         │
│  Output: row streams, mutation results                      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Storage layer  (LMDB-shaped, CoW B+-tree)                  │
│    Page allocator · B+-tree · Txn manager (RO snap, RW)     │
│    Freelist · Page cache                                    │
│  Inputs: bytes keys, bytes values, txn                      │
│  Output: ordered cursor over (key, value)                   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│  Block I/O abstraction                                      │
│    read_page, write_page, sync, n_pages, resize             │
│  Backends: Mem · Unix_file · Mirage_block                   │
└─────────────────────────────────────────────────────────────┘
```

### Design rules

1. **Storage layer is SQL-agnostic.** Operates on opaque bytes. Reusable as
   a standalone KV library.
2. **Block I/O is a functor parameter.** Storage is functorized over a
   `BLOCK` module type. `Mem`, `Unix_file`, `Mirage_block` are three
   implementations available from day 1.
3. **Async only at the page-fetch boundary.** B+-tree algorithms operate
   on in-memory `Cstruct.t` page buffers; only cache misses are `Lwt.t`-coloured.
4. **The txn manager is the single boundary** between SQL/storage and the
   page writer. WAL slots in there later without touching upper layers.

## 4. Block I/O (`BLOCK` module type)

```ocaml
module type BLOCK = sig
  type t
  type error
  val pp_error : Format.formatter -> error -> unit
  val page_size : int
  val n_pages   : t -> int64
  val read_page  : t -> page_id:int64 -> Cstruct.t -> (unit, error) result Lwt.t
  val write_page : t -> page_id:int64 -> Cstruct.t -> (unit, error) result Lwt.t
  val sync       : t -> (unit, error) result Lwt.t
  val resize     : t -> n_pages:int64 -> (unit, error) result Lwt.t
end
```

Shape mirrors `Mirage_block.S`; the Mirage adapter is ~30 lines.

**Backends from day 1:**
- `Mem` — in-process bytes table; no I/O. Used for tests; fastest feedback.
- `Unix_file` — single file under POSIX. Used for Linux dev.
- `Mirage_block` — wraps any `Mirage_block.S`. Used for unikernel deployment.

The full test suite runs against all three. Identical results required.

## 5. Storage layer

### 5.1 Page format

Page size is fixed at 4096 bytes at file creation time (configurable in a
later version; reserved bytes in header allow this).

Page kinds:
- `Header` — 2 of these, page 0 and page 1, alternating per commit.
- `Branch` — internal B+-tree node (keys + child page-ids).
- `Leaf` — B+-tree leaf (keys + values; or keys only for index trees).
- `Freelist` — page reuse tracking (with freed-at-txn metadata).
- `Overflow` — chained pages for values larger than ~quarter-page.
  *Overflow is a stretch goal for v1.5; flag if real workloads need it sooner.*

Each page begins with a common header:
```
+------+----------+-------+----------+-----+------------------+
| kind | n_keys   | flags | reserved | crc | (kind payload)   |
+------+----------+-------+----------+-----+------------------+
```

CRC32 over the page contents (excluding the CRC field itself) is **mandatory
on header pages**. Other pages carry CRC for diagnostics; verification is
optional in the hot path.

### 5.2 Atomic commit protocol

The whole durability story:

```
Initial state on disk:
  Page 0: Header A (txn_id=N, root=R0, freelist=F0)   ← currently active
  Page 1: Header B (txn_id=N-1, ...)                  ← previous
  Pages 2..: data pages

rw_txn modifies the tree:
  - Modified leaves and ancestors written to NEW pages (CoW)
  - Pages superseded by the txn tracked in pending freelist
  - Root, freelist, etc. live only in the rw_txn object — no header update yet

Commit:
  1. write_page each new data page
  2. write_page new freelist pages
  3. sync                                ← all data on disk, but unreachable
  4. write_page Header B (txn_id=N+1, root=R_new, ...)
  5. sync                                ← THE atomic commit point

After step 5: Header B is now active (higher txn_id wins).
Crash before step 5: Header A still wins → world rewinds to pre-txn state.
Crash mid step 4: torn write detected by checksum; Header A used.

Each commit alternates A ↔ B.
```

No journal. No WAL. No fsync of metadata. **Two fsyncs per commit.**

### 5.3 Crash recovery on `Db.open_`

```
Read page 0 and page 1.
Verify each via CRC32.
Pick the valid header with the highest txn_id.
That is the live state. No replay.
```

If both headers are corrupt: surface `Corruption _`. No silent half-recovery.

### 5.4 RO snapshot mechanics

Multi-reader correctness rests on the page allocator respecting active readers.

- `ro_begin` reads the live header → captures `(root, txn_id)` → registers
  in an in-memory `active_readers` table.
- The allocator only reuses freelist entries with `freed_at_txn_id <
  min(active_readers.txn_id)`. Freed pages otherwise wait.
- `ro_end` updates the table; previously-blocked freelist entries become
  reusable when no reader pins them.

All cross-txn coordination is in-memory in the open `Store.t`. No shared
file state.

### 5.5 Public storage API

```ocaml
module Store : sig
  type t
  type ro                              (* phantom *)
  type rw                              (* phantom *)
  type 'a txn                          (* abstract; 'a is ro or rw *)
  type tree_id = int                   (* logical namespace inside the file *)
  type cursor

  val open_  : (module BLOCK) -> path:string -> t Lwt.t
  val close  : t -> unit Lwt.t

  val ro_begin  : t -> ro txn Lwt.t
  val rw_begin  : t -> rw txn Lwt.t    (* serialized by mutex *)
  val commit    : rw txn -> unit Lwt.t
  val rollback  : rw txn -> unit Lwt.t
  val ro_end    : ro txn -> unit Lwt.t

  val get   : _ txn -> tree_id -> bytes -> bytes option Lwt.t
  val put   : rw txn -> tree_id -> bytes -> bytes -> unit Lwt.t
  val del   : rw txn -> tree_id -> bytes -> unit Lwt.t

  val cursor_open  : _ txn -> tree_id -> cursor Lwt.t
  val cursor_seek  : cursor -> bytes -> [`Found | `Not_found_after of bytes]
  val cursor_next  : cursor -> (bytes * bytes) option
  val cursor_close : cursor -> unit
end
```

### 5.6 Concurrency model

- **Single rw_txn at a time**, enforced by a `Lwt_mutex` around `rw_begin`.
  Concurrent writers queue.
- **Many ro_txns concurrent with each other and with the rw_txn.** Snapshot
  isolation.
- Cursors are single-fiber. A cursor must not be shared between fibers.

## 6. Relational layer

### 6.1 Catalog (system tables)

Schema lives in storage as rows in well-known `tree_id`s. No separate
metadata file. DDL is just an rw_txn that writes catalog rows.

| `tree_id` | Name | Purpose |
|---|---|---|
| 0 | `_sys_tables` | one row per user table: name, root_tree_id, created_txn |
| 1 | `_sys_columns` | one row per column: table, ordinal, name, type, NOT NULL, default, PK pos |
| 2 | `_sys_indexes` | one row per index: name, table, columns, unique, root_tree_id |
| 3 | `_sys_meta` | one row: file format version, page_size, schema_version |
| 16+ | user tables and indexes | each a `tree_id` allocated on CREATE |

`Db.open_` reads the catalog into an in-memory cache. DDL bumps a
`schema_version` counter; concurrent ro_txns continue with their snapshot's
schema; new statements after a DDL re-read.

### 6.2 Row identity (rowid)

Every table row has an implicit 64-bit signed `rowid` used as the primary
B+-tree key for the table's data tree. Rules:

- If the table has a *single-column* `INTEGER PRIMARY KEY`, that column
  **is** the rowid (alias). User assigns it; engine validates uniqueness.
- Composite primary keys do **not** become the rowid. The PK is enforced
  via a unique secondary index. The engine auto-assigns rowids.
- If no PK is declared, or the PK is non-INTEGER / composite, the engine
  auto-assigns a monotonically increasing rowid on INSERT. The next-rowid
  counter is stored in `_sys_tables` per table.
- Rowid is the encoding for the table tree's keys. Secondary index entries
  always carry the rowid as their tail (yes, even for unique indexes — it
  simplifies cursor logic and costs 8 bytes per entry).

### 6.3 Row encoding

Per-row, schema-aware codec. For a row of N columns:

```
+----------+------------+----------+----------+
| n_cols   | null_bmp   | values...           |
+----------+------------+----------+----------+
```

- `n_cols` varint (sanity check against schema).
- `null_bmp` ceil(N/8) bytes; bit set means column is NULL.
- `values` in column order. Encoding per type:
  - INTEGER: zigzag varint
  - REAL: 8-byte little-endian float64
  - TEXT: varint length prefix + UTF-8 bytes
  - BLOB: varint length prefix + bytes

Round-trip is the property tested most aggressively.

### 6.4 Index key encoding

Index keys are tuples `(col1, col2, …, rowid)`. Encoding must be
**order-preserving** under bytewise comparison so the B+-tree's natural
ordering yields correct SQL ordering.

Per-type order-preserving codec:
- INTEGER: 8-byte big-endian, with sign bit flipped (so negatives sort before positives).
- REAL: 8-byte big-endian; manipulate sign + exponent so float ordering matches bytewise.
- TEXT: UTF-8 bytes + 0x00 sentinel (escaping any 0x00 in the input).
- BLOB: same scheme as TEXT.
- NULL: a low sentinel byte (configurable per-column for NULLS FIRST/LAST — flagged as open question).

Append `rowid` (8-byte big-endian, sign flipped) to make non-unique index
entries individually addressable.

## 7. SQL layer

### 7.1 Parser

Menhir grammar in `parser.mly`. Hand-written lexer in `lexer.mll`. Grammar
shape borrows from SQLite's `parse.y` for surface syntax familiarity but is
written fresh. AST is an OCaml ADT with location info on every node.

### 7.2 Sema

Single pass over the AST:
- Resolves names (table → table_id, column → column ref).
- Type-checks expressions.
- Expands `*`.
- Validates DDL (no duplicate columns, valid types, etc.).
- Returns a "bound AST" with refs instead of names.

Errors here surface as `Sema | Type_mismatch` variants with source location.

### 7.3 Planner

Rule-based for v1. Two-stage:

**Logical plan:** standard relational algebra ADT.
```ocaml
type logical =
  | Scan of table_ref
  | Filter of expr * logical
  | Project of expr list * logical
  | Join of join_kind * expr * logical * logical
  | Aggregate of group_by * agg_exprs * logical
  | Sort of order_keys * logical
  | Limit of int * int option * logical
```

**Logical → physical** rules:
- Equality predicate on indexed column → `IndexLookup` / `IndexRangeScan`.
- Otherwise → `SeqScan`.
- Join with equi-predicate on indexed column → `NestedLoopJoin` driving
  inner via `IndexLookup`.
- Join with equi-predicate on non-indexed columns → `HashJoin`. Without
  statistics, build side is fixed (right-side build) in v1; revisit when
  stats land.
- Predicate pushdown: filters that reference only one side of a join push
  past the join.

No cost-based optimization in v1. Cardinality estimates: not used.
Statistics: not collected.

### 7.4 Exec — Volcano operators

Each operator implements:
```ocaml
module type Operator = sig
  type t
  val open_ : t -> unit Lwt.t
  val next  : t -> row option Lwt.t
  val close : t -> unit Lwt.t
end
```

v1 operators: `SeqScan`, `IndexLookup`, `IndexRangeScan`, `Filter`,
`Project`, `NestedLoopJoin`, `HashJoin`, `Sort`, `Limit`, `Aggregate`,
`Insert`, `Update`, `Delete`.

Mutation operators consume their input stream and apply changes within
the current rw_txn.

## 8. Public API

```ocaml
module Db : sig
  type t
  type stmt
  type value =
    | V_int of int64
    | V_real of float
    | V_text of string
    | V_blob of bytes
    | V_null
  type row = value array
  type error = ...                  (* see § 9 *)

  val open_     : (module BLOCK) -> path:string -> (t, error) result Lwt.t
  val close     : t -> unit Lwt.t

  val execute   : t -> string -> params:value list ->
                  (int, error) result Lwt.t           (* rows affected *)
  val query     : t -> string -> params:value list ->
                  (row Lwt_stream.t, error) result Lwt.t

  val prepare   : t -> string -> (stmt, error) result Lwt.t
  val run       : stmt -> params:value list ->
                  (int, error) result Lwt.t
  val iter      : stmt -> params:value list ->
                  (row Lwt_stream.t, error) result Lwt.t
  val finalize  : stmt -> unit Lwt.t
end
```

A future ergonomic wrapper (`Db_eio`, etc.) can be layered on top without
changing the core.

**Stream lifecycle.** A `query` opens an `ro_txn` that is held until the
returned `row Lwt_stream.t` is fully consumed *or* explicitly closed via
`Lwt_stream.junk_while` / `Lwt_stream.junk_old`. Callers that abandon a
stream without consuming it leak a reader and block freelist reuse. The
public API exposes a helper `Db.with_query : t -> string -> ... -> (row
Lwt_stream.t -> 'a Lwt.t) -> 'a Lwt.t` that guarantees txn cleanup; users
should prefer it.

**Process isolation.** A single `Unix_file` database opened by two
processes simultaneously would corrupt the freelist (the active-readers
table is in-process). v1 assumes single-process access. The Unix backend
takes an OS-level advisory lock (`flock(LOCK_EX)`) on the file at open and
fails fast if held. Multi-process is not a v1 goal and not on the roadmap;
the lock is a guardrail, not a feature.

## 9. Error model

Three categories, three policies:

| Category | Examples | Policy |
|---|---|---|
| **User errors** | bad SQL, type mismatch, NOT NULL/UNIQUE violation, unknown table | Structured `result` with error variant + source location |
| **I/O errors** | disk full, read failure, mirage-block fault | Propagate as `result`; current rw_txn rolls back automatically |
| **Corruption / programming errors** | bad page checksum, B+-tree invariant violated, type system bug | Raise; surface to caller as `Corruption _`; `Db.t` poisoned |

```ocaml
type error =
  | Parse  of { msg : string; loc : Loc.t }
  | Sema   of { msg : string; loc : Loc.t }
  | Constraint of constraint_kind * string
  | Type_mismatch of { expected : ty; got : ty; loc : Loc.t }
  | Storage_io of string
  | Corruption of string
  | Commit_uncertain of string         (* I/O failure during commit *)
```

Boundary discipline:
- Storage layer never raises on user-driven inputs.
- Encoding layer raises only on internal contract violations.
- SQL layer converts all user-driven errors into structured `error`.
- Internal `Lwt` exceptions are caught and converted at the public boundary.

Transaction semantics:
- Error in explicit BEGIN block → connection is "needs-rollback"; rejects
  everything but `ROLLBACK`.
- Error in implicit one-shot txn → automatic rollback; connection reusable.
- Error during `commit` → `Commit_uncertain`; user must close + reopen.

Corruption is one-way: detected corruption poisons the `Db.t`. No silent
auto-repair.

## 10. Data flow

### 10.1 Read query: `SELECT name FROM users WHERE id = 42`

```
SQL string
  ↓ Lexer + Parser
AST: Select { from = Table "users"; where = Eq(Col "id", Lit 42); proj = [Col "name"] }
  ↓ Sema (catalog lookup, type check)
Bound AST
  ↓ Planner (rule: PK equality → point lookup)
Physical: Project[name] ← IndexLookup[users_pkey, key=42]
  ↓ Exec
ro_txn opens; cursor_seek on users_pkey tree → leaf entry → rowid →
  Store.get on users_data tree → row bytes → Row.decode →
  project [name] → emit. Close ro_txn.
```

Result: `row Lwt_stream.t`. Caller streams without materialization.

### 10.2 Mutation: `INSERT INTO users (id, name) VALUES (42, 'a')`

```
Parse → Sema → Plan: Insert { table = users_id; rows = [...] }
  ↓ Exec
rw_begin (acquires write mutex; queues if held)
  Validate row vs schema
  Encode → row bytes
  Store.put on users_data: rowid_key → row_bytes
  For each index on users:
    Encode index key from indexed cols + rowid
    Store.put on idx_tree_id: index_key → empty
  commit (atomic)
  Return rows_affected = 1
```

### 10.3 Multi-statement transaction

```
BEGIN     → execute opens rw_txn, stashes on connection. No commit yet.
INSERT …  → uses stashed rw_txn (or opens implicit one-shot if none).
SELECT …  → uses stashed rw_txn (read-your-writes via CoW chain).
COMMIT    → Store.commit on stashed rw_txn. Clear from connection.
ROLLBACK  → Store.rollback. Clear from connection.
```

Reads outside any explicit txn use a fresh `ro_txn` per statement.

## 11. Testing strategy

Five tiers:

1. **Unit (Alcotest):** per-module correctness — encoding round-trips,
   B+-tree invariants, planner output for canonical queries.
2. **Property (QCheck):** B+-tree-stays-sorted, freelist gating under
   active readers, snapshot isolation invariants, encode/decode round-trip,
   crash-recovery state-machine.
3. **Mined SQLite SQL corpus:** TCL parser extracts `do_execsql_test`
   blocks → `(name, sql, expected)` triples → run under our engine →
   diff. Filter unsupported features with reason codes. Track conformance %.
4. **Crash tests:** custom `BLOCK` wrapper simulating torn writes + power
   loss at every sync boundary. Property: any successful `commit` survives,
   any uncommitted txn does not.
5. **Multi-backend conformance:** the full suite runs against `Mem` +
   `Unix_file` + `Mirage_block`. Identical results required.

The corpus mining tool is the highest-leverage piece of test infrastructure
to invest in. Output a `skipped.csv` with reason codes per skipped test for
audit.

## 12. Phasing

Walking-skeleton sequence. Solo-developer-feel estimates.

| Phase | Storage | SQL features | Goal |
|---|---|---|---|
| 0 (~4-6w) | Mem | CREATE TABLE, INSERT, simple SELECT | End-to-end demo |
| 1 (~6-8w) | + Unix_file (CoW B+-tree) | + ORDER BY, LIMIT, single-col indexes | Real persistence |
| 2 (~8-10w) | (no change) | + UPDATE, DELETE, joins, GROUP BY, aggregates | Realistic queries |
| 3 (~6w) | + RO snapshots, RW txn | + BEGIN/COMMIT/ROLLBACK | MVCC correct |
| 4 (~4w) | + Mirage_block | (no SQL change) | Runs in unikernel |
| 5 (later) | (no change) | FTS index | v2 |
