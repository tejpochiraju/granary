# Phase 32: INSTEAD OF UPDATE, Session Functions, Multi-column FK

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three SQL features: (1) INSTEAD OF UPDATE triggers completing the trigger matrix; (2) session-state functions CHANGES/LAST_INSERT_ROWID and random functions RANDOM/RANDOMBLOB; (3) multi-column FOREIGN KEY constraints (FOREIGN KEY (a,b) REFERENCES parent(x,y)).

**Architecture:** Task 1 adds one `S_update` match arm in `execute_instead_of` in `db.ml`, between `S_delete` and the catch-all. Task 2 extends `Db.t` with two mutable fields, adds two plan operators intercepted in `db.ml`'s `query` function before reaching `exec.ml`, and adds stateless `eval_func` arms for RANDOM/RANDOMBLOB. Task 3 renames `Cat.fk_constraint` fields from `fk_local_col : string` to `fk_local_cols : string list` (and same for parent), updates comma-separated encoding (backward-compatible), removes the `Unsupported` guard in `sema.ml`, and updates every FK-touching site in `exec.ml` and `planner.ml` to work with lists.

### Background

`execute_instead_of` in `db.ml` is called when `compile` returns `Error (Sema (Unknown_table view_name))` and the SQL targets a known view. It pattern-matches the parsed AST. Phase 31 added `S_insert` and `S_delete`. The `| _ ->` catch-all returns an Unsupported error for UPDATE.

The `subst_new_old` function substitutes `NEW.col` references in trigger body statements. For UPDATE, `new_row` comes from the assignments. The `make_col_schema`, `eval_insert_ast_value`, `find_instead_of`, `subst_new_old`, and `fire_trigger_stmt` helpers are all in `db.ml`'s local scope — no imports needed.

### Background

- `CHANGES()` and `LAST_INSERT_ROWID()` are session-state functions that read mutable state from `Db.t`. They are plumbed through two new plan operators (`Op_changes`, `Op_last_insert_rowid`) intercepted in `db.ml`'s `query` function before the call reaches `exec.ml`.
- `RANDOM()` and `RANDOMBLOB(n)` are stateless and implemented purely in `eval_func` in `exec.ml`.
- Updating the counters: after every successful DML in `execute_change_count`, store `n` in `t.last_changes`; after INSERT, read `next_rowid - 1` from the catalog to update `t.last_insert_rowid`.

  (* ── RANDOM ──────────────────────────────────────────────────── *)
  | Ast.Fn_random, [] ->
    (* Produce a random 64-bit integer (may be negative) using OCaml's Random module.
       Random.bits gives 30 random bits each call; combine three calls for 63 bits,
       then flip the sign bit randomly for full signed 64-bit range. *)
    let b0 = Int64.of_int (Random.bits ()) in  (* bits 0–29 *)
    let b1 = Int64.of_int (Random.bits ()) in  (* bits 30–59 *)
    let b2 = Int64.of_int (Random.bits ()) in  (* bits 60–62 — only 3 bits used *)
    let sign = if Random.bool () then Int64.min_int else 0L in
    let v =
      Int64.logor sign
        (Int64.logor
          (Int64.shift_left b2 60)
          (Int64.logor (Int64.shift_left b1 30) b0))
    in
    Row.V_int v

  | Ast.Fn_random, _ -> Row.V_null

  (* ── RANDOMBLOB ───────────────────────────────────────────────── *)
  | Ast.Fn_randomblob, [Row.V_int n] when n >= 0L ->
    let len = Int64.to_int n in
    Row.V_blob (Bytes.init len (fun _ -> Char.chr (Random.int 256)))

  | Ast.Fn_randomblob, _ -> Row.V_null

     These fallback arms handle the rare case where they appear inside
     complex expressions (e.g. WHERE clauses) that reach eval_func directly. *)

  | Ast.Fn_changes, _ -> Row.V_null
  | Ast.Fn_last_insert_rowid, [] -> Row.V_int 0L
  | Ast.Fn_last_insert_rowid, _ -> Row.V_null

### Background

Currently `Cat.fk_constraint` has `fk_local_col : string` and `fk_parent_col : string`. This plan renames them to `fk_local_cols : string list` and `fk_parent_cols : string list`. Single-column FKs become one-element lists — all existing enforcement code generalizes to lists.

The encoding format (tab-separated text, one line per FK) is updated to use comma-separated column names for the local and parent fields. Existing single-column FKs like `"id"` decode as `["id"]` (splitting `"id"` on `,` gives `["id"]`). This is backward-compatible with data on disk.

**Warning:** After renaming the record fields in `catalog.mli`/`catalog.ml`, the build will fail with ~30 errors in `exec.ml` and `planner.ml`. Fix ALL of them before attempting to build — do not build until all field references are updated.

    ~(child_col_idxs : int list) ~(parent_vals : Row.value list) =
  let schema = child_meta.Cat.columns in
  let* cur   = S.cursor_open tx child_meta.Cat.tree_id in
  let _sr    = S.cursor_first cur in
  let buf    = ref [] in
  let rec scan () =
    match S.cursor_next cur with
    | None -> ()
    | Some (kbytes, vbytes) ->
      let rowid = Rowid.decode kbytes in
      let row   = Row.decode schema vbytes in

        compare_values row.(ci) pv = 0

      if all_match then buf := (rowid, row) :: !buf;

  in

  S.cursor_close cur;

## Implementation Gotchas

1. **fk_local_cols rename causes ~30 compile errors in exec.ml**: After renaming fields in catalog.mli/ml, do NOT attempt a build until ALL field accesses in exec.ml, planner.ml, and the catalog itself are updated. The compiler will list every broken line — fix them all in one pass.

2. **`find_col_idx` (returns `option`) vs `find_col_idx_by_name` (raises)**: The existing `find_col_idx` in `execute_insert` returns `option`. The existing `find_col_idx_by_name` in cascade functions raises on not-found. Use the appropriate one for each context. The new `find_col_idx_by_name_opt` added in Step 3.9 returns `option` for safe use in cascade code.

3. **Warning-8 is a compile error**: Every `match` over `op` type must include the new `Op_changes` and `Op_last_insert_rowid` variants. The build will fail with "this pattern-matching is not exhaustive" if any are missed.

4. **RANDOM() range**: OCaml's `Random.bits()` returns 30 bits (0..2^30-1). Three calls give 90 bits, of which we use 63 + sign bit = 64-bit signed range. The implementation in Step 2.6 combines three 30-bit values with bit shifting.

5. **LAST_INSERT_ROWID after multi-row INSERT**: `INSERT INTO t VALUES (1), (2), (3)` allocates rowids sequentially. After execution, `next_rowid = 4`, so `next_rowid - 1 = 3` correctly gives the last rowid.

6. **CHANGES() returns 0 for DDL**: Only `execute_change_count` updates `last_changes`. CREATE TABLE, ALTER TABLE, CREATE VIEW etc. go through `execute` (returns `unit`) or the DDL fast-paths in `execute_change_count` that return `Ok 0` before reaching `execute_with_count`. So `last_changes` stays 0 after DDL — which matches SQLite behavior.

7. **Multi-col FK encoding is backward-compatible**: Existing single-column FKs stored as `"id\tparent\tpk\trestrict\trestrict"` decode correctly: `String.split_on_char ',' "id"` = `["id"]`. No migration needed.

8. **`pragma_foreign_key_list` returns joined strings**: SQLite returns one row per column pair (seq 0, 1, ... for multi-col FKs). Phase 32 returns one row per FK constraint with comma-joined column names — this passes our comparison tests (which only check `COUNT(*)`). Full SQLite compatibility can come later.

9. **`cascade_update_col_in_tx` is called per-column**: For a multi-col FK on UPDATE CASCADE, the function gets called once per updated parent column. The `fk_pos` lookup finds which FK column corresponds to the updated parent column, so the cascade applies the correct child column.

10. **Task ordering is flexible**: Tasks 1, 2, and 3 are independent. Task 3 is the most invasive (30+ compile errors). Doing 1 and 2 first means any mistakes in Task 3 don't block the other features from working.
