## Task 1: FK DEFERRABLE INITIALLY DEFERRED (#135)

**Background:** All FK constraints are currently IMMEDIATE — checked at the end of each statement (in fact, at the call site that triggers them inside `execute_*`). SQLite supports `DEFERRABLE INITIALLY DEFERRED`, which defers enforcement to commit time, allowing temporary inconsistency within a transaction (e.g. inserting child rows before parents).

**Files:**
- Modify: `lib/sql/parser.mly` — accept `DEFERRABLE INITIALLY DEFERRED|IMMEDIATE` and `NOT DEFERRABLE`
- Modify: `lib/sql/lexer.mll` — add `DEFERRABLE`, `INITIALLY`, `DEFERRED`, `IMMEDIATE` keywords if absent
- Modify: `lib/sql/ast.ml` — extend column FK clause + table-level FK clause to carry a deferrable flag
- Modify: `lib/catalog/catalog.ml` / `.mli` — add `fk_deferrable : bool` field to `fk_constraint`, backward-compatible encoding (line ~644 `encode_fks`, line ~660 `decode_fks`)
- Modify: `lib/sql/sema.ml` — pass through the new flag
- Modify: `lib/sql/exec.ml` — route deferred FK violations onto a per-txn pending list rather than raising; drain at commit boundary
- Modify: `lib/db/db.ml` — drain the pending-check list before committing an explicit txn
- Modify: `lib/sql/ast.ml` / parser — add `PRAGMA defer_foreign_keys` runtime override
- Test: `test/test_e2e.ml` — new group `phase35_fk_deferrable`
- Test: `test/test_sqlite_compare.ml` — new group `phase35_fk_deferrable`

### Steps

- [ ] **Step 1.1: Catalog change (backward-compatible).**

In `lib/catalog/catalog.ml`, extend `fk_constraint`:

```ocaml
type fk_constraint = {
  fk_local_cols   : string list;
  fk_parent_table : string;
  fk_parent_cols  : string list;
  fk_on_delete    : fk_action;
  fk_on_update    : fk_action;

}
```

Update `encode_fks` (~line 644): append a 6th tab-separated field. Update `decode_fks` (~660): support both 5-field (old) and 6-field (new) forms, defaulting `fk_deferrable = false` on the 5-field path.

Update all 8 construction sites — find them via:
```bash

```
Each gets `fk_deferrable = <whatever>`. For now default to `false`; the sema-side construction will set true when parser provides it.

- [ ] **Step 1.2: Lexer + parser.**


Attach to the FK reference rule — both column-level `REFERENCES …` and table-level `FOREIGN KEY (…) REFERENCES …`. Thread the flag through the AST FK reference tuple.

- [ ] **Step 1.5: Pending-check list on Db.t.**

In `lib/db/db.ml`, add:

- [ ] **Step 1.6: Exec: route deferred violations.**

In `lib/sql/exec.ml`, every FK enforcement site currently raises via `Lwt.fail_with "FOREIGN KEY constraint failed: ..."`. There are ~6 sites (lines ~1930, 2461, 2792, 3111, plus SET NULL/DEFAULT on NOT NULL columns).

Each site needs to know whether the violating constraint is DEFERRED. Wrap each raise in a helper:

```ocaml
let fk_violation ~deferred ~kind ~table ~rowid ~msg =
  if deferred then
    (* Queue for commit-time check *)
    Db.queue_pending_fk_check ~kind ~table ~rowid ~msg
  else
    Lwt.fail_with msg
```

Since `exec.ml` doesn't currently know about `Db.t`, you'll need to plumb a small callback or move the pending-check accumulator to `Cat.t` (more practical — `Cat.t` is already passed everywhere).

Cleaner: put `pending_fk_checks` on `Cat.t` and expose `Cat.queue_pending_fk` / `Cat.drain_pending_fks` / `Cat.clear_pending_fks`. Then `exec.ml` calls those directly; `db.ml` orchestrates the drain at commit.

For each FK enforcement site, check `fk.fk_deferrable || Cat.get_defer_fks_pragma cat` and route appropriately.

- [ ] **Step 1.7: Commit-time drain.**

In `lib/db/db.ml`, find `commit` and the auto-commit path at the end of `execute` / `execute_change_count`. Before releasing the txn, call:

```ocaml
let* () = drain_pending_fks t in
(* drain re-checks each pending entry; on first failure, raise + rollback *)
```

`drain_pending_fks`:
- For each pending entry, re-run the relevant FK check (the simplest version: look up the row by rowid, evaluate FK presence). If still violated, raise.
- If the row no longer exists (was deleted before commit), drop the entry.
- Clear the list either way.

- [ ] **Step 1.8: PRAGMA defer_foreign_keys.**

Add a runtime PRAGMA mirroring `Pragma_foreign_keys` shape:

```ocaml
| Pragma_defer_foreign_keys              (* read *)
| Pragma_defer_foreign_keys_set of bool  (* set *)
```

Wire through lexer (no new tokens; PRAGMA names are strings), parser dispatch, plan, sema, exec, planner. Mirror the existing `Pragma_foreign_keys_set` path. The flag goes on `Cat.t` (sibling of `fk_enforcement`).

When `defer_foreign_keys = ON`, all FK checks behave as DEFERRED for the duration of the next transaction, regardless of constraint definition. SQLite resets this to OFF at transaction end.

- [ ] **Step 1.9: Tests.**

## Task 2: Relax VIRTUAL generated column restrictions (#137)

**Background:** Phase 33 rejected `CREATE INDEX` on VIRTUAL gen cols and `CHECK` constraints referencing them at bind time. SQLite allows both because it recomputes virtuals on every read. We can match that by recomputing virtuals into a scratch row before index-key extraction and CHECK evaluation.

**Files:**
- Modify: `lib/sql/sema.ml` — remove the Phase 33 bind-time rejection (`virtual_col_referenced_in_expr` guard in `bind_create_index` and `bind_create`'s CHECK scan)
- Modify: `lib/sql/exec.ml` — at every site that calls `get_index_key_values` or evaluates CHECK on a row that may contain virtual cols, compute virtuals into a scratch copy first
- Test: `test/test_e2e.ml` — convert Phase 33's `virtual_in_index_rejected` / `virtual_in_check_rejected` tests from rejection-asserts into behavior-asserts

### Steps

- [ ] **Step 2.1: Find the bind-time guards.**

```bash
grep -n "virtual_col_referenced_in_expr\|CREATE INDEX on VIRTUAL\|CHECK constraint on column" lib/sql/sema.ml
```

Delete the rejection paths. Keep the helper if you reuse it elsewhere; otherwise remove.

- [ ] **Step 2.2: Identify the index/CHECK write paths.**

```bash
grep -n "get_index_key_values" lib/sql/exec.ml
grep -n "check_expr_cache\|eval CHECK\|check_sql" lib/sql/exec.ml
```

Each call site that operates on a row about to be written or just read needs to ensure VIRTUAL columns are populated.

The cleanest approach: introduce `with_computed_virtuals` that takes a row and meta, returns a new row (or mutates a clone) with virtuals filled. Then wrap each index/CHECK eval call.

```ocaml
let with_computed_virtuals clock params (meta : Cat.table_meta) (row : Row.t) : Row.t =
  if not (has_virtual_cols meta.Cat.columns) then row
  else
    let row' = Array.copy row in
    compute_virtual_generated_cols clock params meta row';
    row'
```

For index key extraction during INSERT/UPDATE:
```ocaml
let row_for_idx = with_computed_virtuals clock params table_meta row in
let iks = List.map row_value_to_index_value (get_index_key_values clock params idx table_meta.columns row_for_idx) in
```

For CHECK eval: similarly populate a scratch row before evaluating the cached CHECK plan.

- [ ] **Step 2.3: Update Phase 33's tests.**

In `test/test_e2e.ml`, find the Phase 33 group `phase33_virtual_gen` tests that assert rejection:


- `virtual_in_check_now_supported`: CHECK (c > 0) where c is virtual. INSERT a row that satisfies; passes. INSERT a row that violates; raises.

## Task 3: SQL polish bundle (#140 + #141)

Two small fixes in one commit.

### Step 3a: FK cascade cycle detection (#140)

**Background:** `cascade_delete_row_in_tx` and `cascade_update_col_in_tx` lack cycle detection. A cyclic FK graph with all-CASCADE (or all-SET NULL after Phase 34) actions could recurse indefinitely. In practice the OCaml stack catches it, but we should fail cleanly.

**Fix:** thread a `Hashtbl.(string * int64, unit)` "visited" set through the recursive cascade calls. Skip if `(table, rowid)` already present. Clear on txn release.

- [ ] **Step 3a.1:** Add a parameter to `cascade_delete_row_in_tx` and `cascade_update_col_in_tx`:
  ```ocaml
  ?(visited : (string * int64, unit) Hashtbl.t = Hashtbl.create 16)
  ```
  At the top of each:
  ```ocaml
  let key = (meta.Cat.name, rowid) in
  if Hashtbl.mem visited key then Lwt.return_unit
  else begin
    Hashtbl.add visited key ();
    ... rest ...
  end
  ```
  Forward `visited` on all recursive calls.

- [ ] **Step 3a.2:** Test:
  ```sql
  CREATE TABLE a (id INTEGER PRIMARY KEY, b_id INT);
  CREATE TABLE b (id INTEGER PRIMARY KEY, a_id INT REFERENCES a(id) ON DELETE CASCADE);
  ALTER TABLE a ADD COLUMN b_ref INT REFERENCES b(id) ON DELETE CASCADE;
  INSERT INTO a VALUES (1, NULL);
  INSERT INTO b VALUES (10, 1);
  UPDATE a SET b_ref = 10 WHERE id = 1;
  DELETE FROM a WHERE id = 1;  -- should not infinite-loop
  SELECT COUNT(*) FROM a;       -- 0
  SELECT COUNT(*) FROM b;       -- 0
  ```

### Step 3b: DDL identifier quoting (#141)

**Background:** `ddl_of_table`, `ddl_of_index`, `ddl_of_fts` emit identifiers unquoted. Tables/columns with spaces, keywords, or punctuation round-trip incorrectly through `sqlite_master`.

**Fix:** add `quote_ident : string -> string` near the DDL reconstructors. Apply at every identifier emission site.

- [ ] **Step 3b.1:** Add helper at top of the DDL reconstruction section in `lib/sql/exec.ml`:
  ```ocaml
  let needs_quoting s =
    String.length s = 0 ||
    (let c = s.[0] in not ((c >= 'A' && c <= 'Z') || (c >= 'a' && c <= 'z') || c = '_')) ||
    String.exists (fun c ->
      not ((c >= 'A' && c <= 'Z') || (c >= 'a' && c <= 'z') ||
           (c >= '0' && c <= '9') || c = '_')) s

  let quote_ident s =
    if needs_quoting s then
      "\"" ^ String.concat "\"\"" (String.split_on_char '"' s) ^ "\""
    else s
  ```

- [ ] **Step 3b.2:** Replace all `meta.Cat.name`, column names, and similar in `ddl_of_table`, `ddl_of_index`, `ddl_of_fts` with `quote_ident <name>`.

- [ ] **Step 3b.3:** Test: create a table whose name and column include spaces, query `sqlite_master.sql`, verify the SQL round-trips through the parser (`Parser.parse`).

## Task 4: FTS snippet() byte-for-byte SQLite parity (#7)

**Background:** Our `compute_snippet` (`lib/sql/exec.ml:3813`) uses simplistic centering: finds the first matching token and centers a fixed-width window. SQLite's snippet() picks the window with the most matches and handles prefix-term matches differently. Phase 30 documented the divergence; phase-35 closes it.

**Files:**
- Modify: `lib/sql/exec.ml` — rewrite `compute_snippet` and adjust `fts_query_terms` to carry prefix info
- Modify: `lib/sql/fts_query.ml` — if needed, expose prefix-term info on the query AST
- Test: `test/test_e2e.ml` — existing snippet tests; verify they still pass with new behavior
- Test: `test/test_sqlite_compare.ml` — new snippet cases that diff against real SQLite

### Steps

- [ ] **Step 4.1: Understand SQLite's algorithm.**

SQLite's `snippet(table, expr, start, end, ellipsis, col, n)`:
1. Tokenize the column text.
2. For each window of `|n|` consecutive tokens, count how many positions match the query.
3. Pick the window with the maximum match count. Ties: prefer earlier.
4. If `n < 0`, the window is `|n|` tokens long; if `n > 0`, it's `n` tokens long. (Negative n was the SQLite4 convention; FTS5 uses positive.)
5. Wrap matched tokens with `start`/`end` (default `<b>`/`</b>`).
6. Prepend ellipsis if window doesn't start at token 0; append if doesn't end at last token.
7. Prefix-term matches (from `LIKE 'foo*'` queries): highlight the entire matched token, not just the prefix.

- [ ] **Step 4.2: Rewrite compute_snippet.**

Change `query_terms` to carry prefix info — a list of `(term, [`Exact | `Prefix])` rather than just strings. Update the helper that extracts terms from `Fts_query.t`.

Replace the "first match" centering with "best window" centering: iterate all start positions, count matches in the n-token window, pick argmax (lowest index on ties).

For each token in the chosen window, check both exact matches and prefix matches (`String.starts_with`) to decide highlighting.

- [ ] **Step 4.3: Tests.**

Update or add tests:
- A 100-token document with the query term appearing at positions 5, 50, 80. The window should center around the densest cluster.
- Prefix query (`MATCH 'foo*'`): document with `foo`, `food`, `football`, `foobar`. All should be highlighted.
- Edge case: query term at very start of document — no leading ellipsis.

Add SQLite comparison cases:
```ocaml
("CREATE VIRTUAL TABLE t USING fts5(c); \
  INSERT INTO t VALUES('the quick brown fox jumps over the lazy dog');",
 "SELECT snippet(t, 0, '<b>', '</b>', '...', 8) FROM t WHERE t MATCH 'fox'");
("CREATE VIRTUAL TABLE t USING fts5(c); \
  INSERT INTO t VALUES('foo food foobar football');",
 "SELECT snippet(t, 0, '<b>', '</b>', '...', 8) FROM t WHERE t MATCH 'foo*'");
```

These must produce byte-identical output to sqlite3.
