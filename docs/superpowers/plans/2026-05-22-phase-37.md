# Phase 37 — Storage extensions

**Goal:** Land #43 overflow pages, #120 VACUUM, #122 WITHOUT ROWID. Three issues, ship one feature per commit.

**Approach summary:**

- **#43 Overflow pages** — every leaf value gets a 1-byte tag prefix (`0x00` = inline, `0x01` = chain). When value > inline threshold, allocate an overflow chain (new page kind) and store a 17-byte marker in the leaf cell. Reads detect the tag and follow the chain. `put` over an existing key frees the old chain; `del` frees the chain. Lifts the effective max value size from 1024 B to ~2 GiB. WAL/SAVEPOINT/freelist work transparently since overflow pages are allocated through the Pager. **Bumps the on-disk leaf encoding** (every value is now tag-prefixed) — fresh schema, no migration. Format version stays 1; the v1 file format already assumed the tag prefix exists.
- **#120 VACUUM** — `Store.vacuum t` opens a sibling `~path~.vacuum-tmp` file as a fresh store, walks every tree in the meta tree, copies all (key, value) pairs into the dest via cursor + put (which naturally re-creates overflow chains densely). Commits dest, closes both, atomically renames over the original. Surfaced as `VACUUM` SQL statement and `PRAGMA vacuum`. Acquires the writer mutex internally.
- **#122 WITHOUT ROWID** — parser accepts `WITHOUT ROWID` after the column list; catalog persists a `without_rowid` flag in `_sys_tables`; INSERT uses the encoded PK as the B-tree key instead of a synthetic rowid; SELECT/UPDATE/DELETE seek by PK; secondary indexes store the encoded PK in their value slot in place of the rowid varint.

**Tech stack:** OCaml 5.x, dune 3.x (in podman), lwt, alcotest, qcheck.

## Task 1: Overflow pages

**Files:**
- Modify `lib/storage/page.ml`/`.mli` — add `Overflow` page kind (byte = 4)
- Modify `lib/storage/btree.ml`/`.mli` — tagged leaf values + overflow chain read/write/free
- Modify `lib/store/store.ml` — raise max value size limit
- New test: `test/test_overflow.ml` — large blob roundtrip, chain ≥ 3 pages, replace frees old chain, del frees chain, freelist reuse, WAL coexistence, SAVEPOINT rollback

Inline threshold: 800 B. Values > 800 B spill to overflow. Marker layout: `0x01 | head_pid:u64 | total_size:u64` (17 bytes). Inline layout: `0x00 | original_value`.

Overflow page layout: common header (16 B, kind=Overflow); `right_page` reused as next-page pid (0 = chain end); bytes 16..17 are payload_len uint16; bytes 18..18+payload_len are payload bytes. Max payload per overflow page: `4080 - 2 = 4078` B.

## Task 2: WITHOUT ROWID

**Files:**
- Modify `lib/sql/ast.ml` — `S_create_table` gains `without_rowid: bool`
- Modify `lib/sql/parser.mly` — accept `WITHOUT ROWID` table option
- Modify `lib/catalog/catalog.ml`/`.mli` — `table_meta` gains `without_rowid` flag; `_sys_tables` row format extended with a trailing bool (backward-compatible — old rows decode as `false`)
- Modify `lib/sql/exec.ml` — INSERT/SELECT/UPDATE/DELETE/UPSERT in `without_rowid` tables key the table tree by encoded PK; secondary indexes store encoded PK
- New test: `test/test_without_rowid.ml`

Reject `CREATE TABLE … WITHOUT ROWID` without an explicit PRIMARY KEY.

PK encoding uses `Sqlocaml_encoding.Index_key.encode_key` for consistent collation/order with existing index machinery.

## Task 3: VACUUM

**Files:**
- Modify `lib/store/store.ml`/`.mli` — `val vacuum : t -> unit Lwt.t`

VACUUM is implemented at the store layer: open temp file, copy every tree, commit, close, rename. Atomic rename uses `Unix.rename` (POSIX `rename(2)` is atomic on same filesystem).
