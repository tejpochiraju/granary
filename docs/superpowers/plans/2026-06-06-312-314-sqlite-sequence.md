`lib/catalog/catalog.ml`, in `next_rowid_in_txn` (`:1847`), guard before allocating. Replace the body's allocation with an exhaustion check that fires only for AUTOINCREMENT tables (plain rowid tables keep current behavior — their random-probing is out of scope):

```ocaml
let next_rowid_in_txn t ~name (tx : S.rw S.txn) =
  match Schema_cache.find_table t.sc name with
  | None -> failwith (Printf.sprintf "no table '%s'" name)
  | Some m ->
    (* #312: an AUTOINCREMENT table whose counter is already pinned at max_int
       (a max_int rowid exists) cannot allocate another id.  SQLite raises
       SQLITE_FULL here instead of probing for a free rowid; match its wording.
       Plain rowid tables keep the existing hold-at-max behavior. *)
    if m.autoincrement
       && (not (Int64.equal m.next_rowid empty_next_rowid))
       && Int64.equal m.next_rowid Int64.max_int
    then failwith "database or disk is full"
    else (
      let id, next = alloc_rowid m in
      let m' = { m with next_rowid = next } in
      Schema_cache.bump_rowid t.sc ~name m';
      let%lwt () = S.put tx sys_tables_tid (Bytes.of_string name) (encode_table_value m') in
      Lwt.return id)
;;
```

Note: after an explicit `INSERT ... (a) VALUES (max_int)`, `insert_rowid` (exec.ml:2814) skips the bump (its `n < max_int` guard is false), so `next_rowid` stays at whatever it was. To make the guard fire reliably, also ensure the explicit-max path pins the counter: in `lib/sql/exec.ml` `insert_rowid` (`:2814`), change the `else Lwt.return_unit` arm so an explicit `max_int` for an AUTOINCREMENT table pins `next_rowid` to `max_int`:

           else if table_meta.Cat.autoincrement
           then
             (* #312: pin the AUTOINCREMENT counter at max_int so the next
                auto-allocation detects exhaustion and raises SQLITE_FULL. *)
